# Schema-driven message generation

Every Kafka request/response type except `ApiVersionsRequest` — including the v2
RecordBatch / Record / RecordHeader codecs — is generated by a single compile-time
DSL: each `MessageDef` in `async_kafka/protocol/messages.nim` is expanded by
the `defineKafkaMessage` macro in `async_kafka/protocol/schema.nim`
into a Nim type plus its `encode` / `decode` procs. Runtime primitives
(legacy + KIP-482 compact, tagged-fields trailer, varint helpers) live in
`protocol/primitives.nim`. The request that is not generated is the one that
comes first: the ApiVersions exchange is what establishes the version ranges
every generated codec selects from. Its response is generated like the rest.

The messages and version ranges covered are listed under "Supported Kafka API
versions" in the README.

## What the macro supports

- per-field version gating (`sinceVersion` / `untilVersion`)
- KIP-482 flexible / tagged fields (`flexibleSince`, `taggedId`)
- nullable fields, nested structs, struct arrays
- zigzag varint scalars (`fkVarInt` / `fkNullableVarBytes` / `fkVarString`)
- `arrayCountKind = ackVarint` for varint-counted arrays (e.g.
  Record.headers)
- per-message `contextParams` + per-field `deltaFrom` for batch-relative
  delta encoding (Record's offset / timestamp deltas)
- the `ekRecordBatchV2` envelope (RecordBatch only) which inlines the
  fixed header + CRC32C + optional records-section compression in place
  of the standard field-by-field codec

## Design and verification

The design is informed by
[franz-go](https://github.com/twmb/franz-go)'s `definitions/` format but
uses Nim `const` data + `macro` instead of a separate text DSL so the
schema is type-checked by the Nim compiler. What reaches the wire is
checked against vendored Apache Kafka 3.7.0 message JSON by
`tests/test_wire_spec_drift.nim`, so adding a message means fetching its
upstream JSON into `tests/fixtures/kafka-3.7.0/message/` in the same
change. Record and RecordBatch have no upstream message JSON to compare
against; their bytes are pinned by the hand-written fixtures in
`tests/test_schema_gen.nim`.
